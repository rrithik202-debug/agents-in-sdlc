GitHub Copilot をエージェントモードにすると、コードベースを調べ、変更を提案し、ファイルを編集してコマンドを実行します。作業は開発者のマシン上でリアルタイムに進むため、VS Code の Copilot Chat ではツール呼び出しやファイル編集を逐一確認できます。差分をその場でレビューして個別に受け入れまたは却下し、エディターを離れずに追加プロンプトで作業を調整・拡張できます。

この演習では、アクセシビリティエージェントの作業を監視して変更をレビューし、同じセッションにライトモードの切り替えを追加するよう依頼します。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムに監視します。
- 提案されたファイル変更をレビューして受け入れます。
- セッションの途中でエージェントに指示し、ハイコントラスト モードに加えてライトモードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティエージェントがハイコントラストモードを実装しています。作業中にデザインチームから、既定のテーマが暗すぎると感じる利用者向けにライトモードも追加したいという要望がありました。新しい会話を始めず、既存のセッションに要件を追加します。

## Copilot の進行状況を監視する

Copilot Chat には、エージェントが調査したファイル、実行したコマンド、提案した編集が表示されます。編集は差分と **Keep** / **Undo** の操作とともに会話内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツール呼び出しを確認します。ファイルの読み込みや編集、実行を求められるターミナル コマンドが表示されます。
3. エージェントがファイルの変更を提案すると、差分がチャット内に表示されます。
   - **Keep** を選ぶと変更を受け入れます。
   - **Undo** を選ぶと変更を取り消し、エージェントに再度作業させます。
4. Chat 上部の **Files changed** を開くと、このセッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナルコマンドなどの実行に許可が必要な場合、エージェントは **Allow** を表示して一時停止します。内容を確認し、許可してもよいコマンドだけを承認します。

5. エージェントがハイコントラスト モードの実装を終えるまで待ちます。最後に変更内容をまとめたメッセージが表示されます。

## ライトモードを追加するようエージェントを方向付ける

同じ会話を続けると、エージェントは先ほどの変更、スタイル方法、local storage の使い方をコンテキストとして保持できます。

1. Copilot Chat の入力欄に次のプロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントが前の作業を引き継ぎ、すでに行った変更を確認してライトモードの追加を提案する様子を見ます。
3. それぞれの差分をレビューし、差分ごとに **Keep** または **Undo** を選択します。
4. たとえばトグル UI のリファクタリングなど、望まない方向に進んだ場合は、入力欄の横にある **Stop** で停止し、方向を明確にする追加メッセージを送ります。

> [!TIP]
> 進行中のセッションに追加プロンプトを送ると、最初からやり直すより短時間で方向を調整できます。たとえば、CSS のセレクターの重複を避けて CSS 変数を使うよう依頼したり、既存の設定パネルにライトモードを組み込むよう修正したり、両方の切り替えにキーボード ショートカットを追加したりできます。

## 変更全体をレビューする

コミットする前に、エージェントが変更したファイルを確認します。

1. VS Code で **Source Control** ビューを開きます。
2. エージェントが変更したファイルの一覧をすべて確認します。Astro コンポーネント、スタイル、関連テストなどが含まれるはずです。
3. 変更されたファイルを開いて差分を確認します。Accessible Rich Internet Applications (ARIA) 属性、キーボード操作、セマンティック HTML、local storage による設定保持などを確認します。
4. 問題がなければ **Source Control** パネルから変更をステージしてコミットします。次の演習で公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードで、進行中のセッションを監視して方向付けました。ファイルの編集を逐一レビューして受け入れまたは却下し、コンテキストを失わずに作業を拡張するフォローアップ プロンプトを送信しました。

この演習では、次のことを行いました。

- エージェントの作業をリアルタイムに監視しました。
- 個々のファイル編集を受け入れ、または却下しました。
- フォローアップ プロンプトでセッションの途中から方向を調整しました。
